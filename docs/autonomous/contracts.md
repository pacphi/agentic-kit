# Autonomous Experimentation Contract Specification

> **For agentic workers:** Use this specification with the [master plan](implementation-plan.md). Implement it through the checked tasks in the foundation and learning plans.

**Goal:** Define the exact boundaries needed to connect supervised execution to autonomous experiment selection.

**Architecture:** Separate an `ak` observation DTO from the LAB evidence bundle, policy admission, and durable champion transaction. Treat all subprocess output and upstream receipts as untrusted inputs until validated against pinned local policy.

**Tech stack:** JSON Schema, JSDoc/TypeScript, Node crypto and SQLite, real upstream Flywheel interfaces, and a bounded Rust JSONL bridge.

**Spec:** [Research recommendation](ruvnet-evolution-adoption.md) and [master constraints](implementation-plan.md#global-constraints).

## Global constraints

All limits below are proposed initial policy values. They become enforceable only after grant activation and runtime qualification. Unknown data stays unknown. All new schemas reject additional properties, non-finite numbers, prototype keys and unsupported versions.

## C1 — public `ak` observation

Add proposed flags `--json --result-profile companion-v1`. The profile requires `--json`; unknown profiles return exit 2 before worker launch. Legacy `--json` retains `{plan, results}`. A valid profile invocation produces exactly one bounded JSON document on stdout; parser/runtime failures before command dispatch may lack it and are adapter-level failures, never success.

```ts
type Provenance = 'observed' | 'configured' | 'inferred' | 'unknown';
type Cleanup = 'not-started' | 'adapter-reported' | 'orphaned' | 'unknown';
type ResultStatus = 'planned' | 'succeeded' | 'failed' | 'cancelled'
  | 'timed_out' | 'blocked' | 'invalid';
interface CompanionResult {
  schema: 'ak.companion-result/v1';
  runId: string; // random UUID generated by ak, not a task-derived identifier
  template: 'feature' | 'security' | 'refactor' | 'packaging' | 'release' | null;
  status: ResultStatus;
  reasonCode: 'none' | 'invalid-request' | 'host-alignment'
    | 'execution-failure' | 'cancelled' | 'export-invalid';
  timing: { startedAt: string; endedAt: string; durationMs: number };
  sourceObservation: { head: string | null; dirty: boolean | null };
  workers: PublicWorker[];
}
interface PublicWorker {
  workerId: string; activity: string; host: string;
  status: Exclude<ResultStatus, 'planned' | 'invalid'>;
  exitCategory: string; // exact existing EXIT_CATEGORIES enum
  configuredModel: string | null; observedModel: string | null;
  provider: string | null; providerProvenance: Provenance;
  durationMs: number; cleanup: Cleanup;
  attempts: Array<{ host: string; model: string | null;
    status: string; exitCategory: string; durationMs: number }>;
  usage: { inputTokens: number | null; outputTokens: number | null;
    source: 'observed' | 'unknown' };
}
```

`workerId`, activity and host must match the materialized plan and admitted host catalog. Model/provider strings must match the pinned catalog used by the exporter; unknown observations become null with unknown provenance. Do not emit arbitrary strings merely because they match a permissive regex. Numeric usage maps only known host fields; absent/unsupported usage is null, never zero.

Maximum document size: 128 KiB UTF-8. At most 32 workers, 8 attempts per worker; identifiers at most 96 characters, model IDs at most 160, ISO timestamps at most 32. If validation or size enforcement fails, emit a small `export-invalid` failure DTO with no workers and exit 1. Never truncate an oversized success into an apparent valid success.

No plan, prompt, task text, session/transcript path, runtime handoff, environment, arbitrary failure reason or raw output is exported. All errors use closed reason codes. Dry-run exports `planned`, zero workers, and no execution evidence. Source observations are not immutable source identities: LAB separately seals source inputs and resulting artifacts.

The current worker schema does not prove process-tree termination. `adapter-reported` means the existing adapter returned without an orphan finding; it is weaker than the independently observed container cleanup in C3. The overall experiment cannot pass with `orphaned` or unknown runtime cleanup.

## C2 — laboratory policy and grant

`LAB/config/lab.json` is requested configuration. `STATE/grants/<digest>.json` is the approved, signed, immutable grant; untrusted candidates cannot write either. The grant binds the canonical policy/config bytes, selected source/toolchain/corpus/verifier catalogs, execution backend, issuing identity, validity period and fencing epoch.

```ts
interface LabLimits {
  maxLanes: number; maxAgentSlots: number; workerConcurrency: number;
  maxGenerations: number; maxCandidatesPerHypothesis: number;
  maxCycleMs: number; maxRunMs: number; maxAttemptMs: number; cleanupGraceMs: number;
  maxStdoutBytes: number; maxStderrBytes: number;
  maxEvidenceBytes: number; maxRetainedWorktrees: number;
  meteredUsdMicros: number; maxInvocations: number;
}
interface LabPolicy {
  schema: 'ak.lab-policy/v1'; id: string;
  executionMode: 'offline' | 'subscription' | 'metered';
  publication: 'local' | 'draft-pr';
  allowedMutationTargets: string[];
  limits: LabLimits;
  sourceCatalogRef: string; verifierCatalogRef: string;
  runtimeQualificationRef: string;
}
interface ActionRequest {
  action: 'research.read' | 'candidate.create' | 'worker.run' | 'verify.run'
    | 'evidence.write' | 'lab.select' | 'lab.rollback' | 'memory.write'
    | 'publish.draft' | 'retention.delete';
  resourceRef: string; grantRef: string; epoch: number;
  reservationRef: string | null; expectedHead: string | null;
}
interface DecisionReceipt {
  schema: 'ak.lab-decision/v1'; id: string; grantRef: string; epoch: number;
  action: ActionRequest['action']; resourceRef: string;
  decision: 'allow' | 'deny'; reasonCodes: string[]; at: string;
}
```

Initial activated profile: maximum 3 lanes, 4 total agent slots, 1 writing worker per worktree, 2 generations, 4 candidates/hypothesis, 60-minute research-cycle budget, 20-minute whole-`ak run` budget, 120-second worker-attempt budget, 10-second cleanup grace, 128 KiB stdout, 64 KiB stderr, 10 MiB evidence/run, 12 retained worktrees and 100 host invocations/day. Maximum daily external metered budget is **zero** until a separate metered profile with a finite positive ceiling is approved.

Every invocation deadline is the earlier of its own maximum and the remaining cycle deadline. A full candidate corpus may exceed one cycle's resources: save completed independent outcomes, end INCONCLUSIVE with a budget reason and resume only after source/host/evaluator freshness checks. Never lower sample requirements or erase the previous day's reservations to force an accepted result.

These are starting ceilings, not throughput promises. Three lanes may be impossible when model-backed verifiers occupy remaining slots. A worker cannot request larger limits, a new host/provider, another signer, network access or more delegation. Experimental routing may choose only approved catalog entries and must never rewrite the user's default routing policy.

`authorize(action, context): DecisionReceipt` checks grant signature, expiry, source/toolchain qualification, current epoch, resource containment and budget reservation immediately before each side effect. Denials are durable and never retried with wider authority. Revocation increments the controller epoch, rejects new work and cancels active dependent work.

## C3 — runtime and whole-workflow adapter

```ts
interface RunRequest {
  invocationId: string; taskRef: string; candidateRef: string;
  kitArtifactRef: string; routePolicyRef: string; grantRef: string;
  epoch: number; deadlineAt: string;
}
interface RuntimeBackend {
  qualify(): Promise<{ qualified: boolean; receiptRef: string;
    reasonCodes: string[] }>;
  start(request: RunRequest): Promise<{ instanceId: string }>;
  observe(instanceId: string, signal: AbortSignal): Promise<{
    exitCode: number | null; stdout: Uint8Array; stderrDigest: string | null;
    outputOverflow: boolean }>;
  cancel(instanceId: string): Promise<void>;
  cleanup(instanceId: string): Promise<{
    state: 'verified' | 'orphaned' | 'unknown'; receiptRef: string }>;
}
interface InvocationResult {
  schema: 'ak.lab-invocation/v1'; invocationId: string;
  result: CompanionResult | null;
  failureCode: 'none' | 'admission-denied' | 'runtime-unavailable'
    | 'deadline' | 'output-overflow' | 'invalid-result' | 'orphaned';
  cleanup: 'verified' | 'orphaned' | 'unknown' | 'not-started';
  evidenceRef: string;
}
```

`runAk(request, dependencies): Promise<InvocationResult>` uses an absolute prequalified `node` plus `ak` artifact path and literal arguments. The profile must include `--json --result-profile companion-v1`, explicit route overrides, `--max-concurrent 1` and a bounded `--timeout`. The task comes from an admitted fixture; no shell-command string or arbitrary executable is supplied by a model.

Before starting, reserve global slots, invocation budget and any priced spend. The overall timer covers preparation, readiness, all worker attempts, evaluation and ordinary completion; cleanup has a separate maximum 10-second grace. On abort, ask `ak` to cancel, then terminate the entire runtime instance if necessary. Detached host process groups mean killing the outer Node PID alone is insufficient.

Core cancellation adds optional `signal` propagation to `executeRunPlan`, escalation and attempt functions; no new DAG scheduler. Pending workers become cancelled, no new attempts launch, and prepared running adapters execute cancellation and cleanup once. Caller cancellation is distinct from timeout. Every listener/timer is removed in `finally`.

Qualify the Linux backend with disposable malicious fixtures: attempted writes outside mounted candidate data, access to controller sockets/home/keys, unapproved network connections, detached descendants, resource exhaustion and cleanup failure. Candidate containers receive no production home or engine socket. Egress denies direct internet; admitted host transports pass through a separately controlled gateway. A candidate cannot bypass the gateway by choosing different proxy settings.

Native delegation and model calls launched from a worker's shell must also be disabled or admitted through the global slot/budget controller. Merely counting top-level `ak` processes misses nested host agents. Qualification must demonstrate denial of an unregistered nested model session; if the selected host transport cannot enforce that boundary, its unattended profile is unqualified. Offline and manually supervised tests can still proceed without claiming full autonomy.

Subscription mode is admitted only when the selected host can authenticate and execute in this boundary; no API fallback. Its dollar cost remains unpriced, bounded by wall time/slot/invocation limits and any observable host quota. Metered mode additionally requires pre-call reservation and a gateway/provider cap; if hard spend enforcement is unavailable, deny metered mode. Environment keys alone never select a mode.

## C4 — source, tasks and outcomes

```ts
interface SourceBinding {
  kitArtifactDigest: string; kitCommit: string;
  targetSnapshotDigest: string; toolchainDigest: string;
  verifierDigest: string; corpusDigest: string; grantRef: string;
}
interface TaskCase {
  id: string; family: 'lifecycle' | 'handoff' | 'ownership' | 'routing' | 'footprint';
  fixtureRef: string; promptRef: string; verifierRef: string;
  split: 'train' | 'development' | 'anchor' | 'acceptance';
  objective: 'quality' | 'latency' | 'footprint';
}
interface TaskOutcome {
  taskId: string; repeat: number; policyRef: string; invocationRef: string;
  verified: boolean; quality: number; hardFailures: string[];
  durationMs: number | null; footprintBytes: number | null;
  cost: { kind: 'observed' | 'estimated' | 'unpriced' | 'unknown';
    usdMicros: number | null; pricingRef: string | null };
}
interface EvaluationBundle {
  schema: 'ak.lab-evaluation/v1'; id: string;
  comparison: 'policy' | 'target-source' | 'kit-source';
  baselineSource: SourceBinding; candidateSource: SourceBinding;
  baselinePolicyRef: string; candidatePolicyRef: string;
  split: TaskCase['split']; outcomes: TaskOutcome[];
  verdict: 'ACCEPT' | 'REJECT' | 'INCONCLUSIVE';
  reasonCodes: string[]; artifactRefs: string[];
}
```

All references are `sha256:` plus 64 lowercase hex digits, except opaque identifiers explicitly described otherwise. Hash immutable artifacts, not mutable directory names. Seal the kit executable/package independently from the target fixture. Candidate outputs are captured after execution as a new manifest, preserving file bytes, relative paths and executable modes; reject symlinks, traversal, unsupported special files and files outside approved paths.

For `policy` comparisons, both source bindings are identical and only the policy changes. `target-source` permits the target snapshot to differ; `kit-source` permits the kit artifact/commit to differ. The grant must name the allowed comparison axis. Toolchain, corpus and verifier remain equal. Record both bindings rather than representing two different binaries with one revision field.

The target snapshot includes all selected tracked and untracked source inputs; ignored/private files are absent by construction. Retain a manifest of included paths rather than claiming HEAD represents dirty state. Do not run baselines and candidates in the same mutable checkout. Baseline/candidate order is alternated across repeats, with fresh workspaces and comparable environment/cache policy.

Initial development corpus: five families × six independent cases = 30 task cases. Use separate train, anchor and acceptance fixture identities; do not copy the same smoke command into all splits. Add 30-case one-use acceptance shards before stochastic automatic selection. Minimum sample counts are admission floors, not evidence of statistical power.

`evaluatePair(baselineRef, candidateRef, suiteRef, context): Promise<EvaluationBundle>` executes the real artifact verifier outside the writer container. Candidate content cannot alter verifier commands or labels. A grader's free-text confidence cannot replace `verified` or hard invariant checks.

## C5 — experiment journal, budgets and memory

Use `STATE/journal.sqlite`, one controller writer, prepared SQL statements, WAL, foreign keys and `synchronous=FULL`. Run `BEGIN IMMEDIATE` for admission, reservation, claim, champion and rollback transactions. Busy timeout is bounded at 2 seconds; never keep a database transaction open while invoking a worker/network operation. Keep migrations versioned and fail on newer schemas.

| Table | Key / contents |
| --- | --- |
| `control` | Singleton: schema version, current epoch, paused flag |
| `grants` | Grant digest, signer, validity, revoked state |
| `events` | Unique dedup key, source reference, event type, state, claim epoch |
| `runs` | Run UUID, source binding, state, deadline, terminal verdict |
| `reservations` | Idempotency key, run, resource kind, reserved/settled integer amount |
| `artifacts` | Digest, relative store path, bytes, media type, verification status |
| `lineage` | Upstream run ID + commit ID, immutable commit bytes/digest |
| `champions` | Experiment family, policy digest, generation, epoch, acceptance receipt |
| `decisions` | Policy/selection/rollback decision bytes and source references |
| `outbox` | Idempotent AgentDB and optional publisher delivery references |

Artifacts are written to a same-filesystem temporary file with exclusive creation, flushed, renamed to a content-addressed path, and directory-flushed where supported. Verify bytes by readback before a transaction can reference an artifact as complete. A crash may leave an unreferenced blob, never a champion pointing to a missing blob. Failed writes return a failure, not a successful checkpoint.

Reservations charge all parallel lanes through one journal. `reserve(key, kind, maximum)` is idempotent; available amount is ceiling minus settled amounts minus active reservations. Settle observed usage when trustworthy. On a crashed or unpriced metered call, retain its full reservation until reconciliation; never release it just because the child disappeared. Integer microdollars avoid floating accounting drift.

AgentDB receives only sanitized findings, verification grades and evidence references through the existing Ruflo structured memory tools. Write an outbox record in the run's terminal transaction; retry delivery with the same memory key. An unavailable memory server does not erase evidence or repeat a completed expensive experiment. It reports `memory-pending`; the journal is operational state, not an alternative semantic memory system.

## C6 — search winners and durable champions

The actual Flywheel `Policy` uses string-valued fields; `Score` contains only `primary`, `noopRate`, `costPerWin`, and `regressed`. Its promotion callback lacks the full source-bound per-task evidence. Use it for **provisional development search**, then independently validate the candidate through the richer acceptance API below. Do not call an upstream `PROMOTED` lineage row a durably accepted LAB champion.

```ts
interface SelectionDecision {
  eligible: boolean; reasonCodes: string[];
  acceptanceRef: string; anchorRef: string; gateDigest: string;
}
function judgeCandidate(bundle: EvaluationBundle,
  anchor: EvaluationBundle, gate: GatePolicy): SelectionDecision;
interface GatePolicy {
  schema: 'ak.lab-gate/v1'; objective: TaskCase['objective'];
  minPairs: number; minRelativeGain: number;
  bootstrapSamples: number; maxSelectionsPerShard: number;
}
interface ChampionStore {
  select(request: { family: string; expectedPolicyRef: string;
    candidateRef: string; epoch: number; decision: SelectionDecision }): Promise<boolean>;
  rollback(request: { family: string; expectedPolicyRef: string;
    parentRef: string; epoch: number; reasonRef: string }): Promise<boolean>;
}
```

Initial gate: no hard failure, source/toolchain/grant/verifier identities valid and equal where required, verified cleanup, no anchor regression, one candidate per acceptance shard, at least 30 independent paired task IDs. Repeats are clustered by task, not counted as independent cases. Reject non-finite/missing metric values.

For deterministic correctness fixes, require an explicit reproducer improvement plus all unaffected anchor cases passing; label this deterministic evidence without invented significance. For stochastic quality selection, use a paired task-cluster bootstrap with 10,000 samples and a seed derived from the evaluation digest; require the one-sided 95% lower confidence bound of quality gain above zero. For latency/footprint objectives require no task-quality regressions and a lower confidence bound of relative improvement at least 0.05. These are proposed gates; approve their complete canonical values once, never let a candidate edit them.

Only the acceptance service can access unseen shard content. Consume the shard after a single candidate decision; provision another independently generated shard before the next attempt. Report insufficient corpus as inconclusive. Merely renaming/reordering reused tasks or adjusting alpha does not remove adaptive overfitting.

Selection protocol: verify evidence blobs → persist signed LAB acceptance receipt → transactionally recheck grant/epoch/expected champion and insert decision plus new pointer → commit → read back pointer. A write, signature, grant, epoch or compare-and-swap failure leaves the old champion intact. The signer belongs to LAB and grants no Ruflo or release authority. The gate digest binds source bytes **and configuration**, not only `Function.toString()`.

Flywheel's `onGeneration` hook swallows exceptions. Use its injected `LineageStore.append` for durable upstream rows and make the LAB selection transaction authoritative. Generation callbacks remain reporting/resume hints; every resumed run validates all referenced evidence, grant, spend reservations and root/source identities. [Inspected Flywheel implementation](https://github.com/ruvnet/metaharness/blob/d5833dc6512ac1adeeef91a331c29055cd8a4dbb/packages/flywheel/src/run.ts).

## C7 — Dream, scheduling and publication

The bridge invokes the real Dream compiler with validated source-specific configuration and records compiler artifact, config and compiled-prompt digests. It does not execute the bundled `dream-nightly.mjs`. Add a reviewed compiler publication-policy seam for a genuinely local routine; exact-version patch provenance is mandatory until upstream publishes that seam. Do not strip arbitrary Markdown steps with a fragile regex or claim `autoMerge:false` disables publication.

Candidate agents may write only their own snapshot. Compiled instructions cannot call the publisher directly. The separately credentialed publisher accepts only an existing signed, sanitized artifact digest and matching active grant; default `publication=local` never makes a remote call. Source, metadata, gists, issue comments and prompts are all potential publication channels covered by the same capability boundary.

Scheduler: `nightly`, `source-changed`, `host-changed`, `incident` event types; dedup key is hash of type + source digest + UTC time bucket or incident ID. One controller claims work transactionally. Three manual complete cycles precede activation. Persistent timer triggers enqueue/run; no assumption that `dream-machine schedule` registers a job.

Loop states: `queued → admitted → preparing → running → verifying → terminal`. Terminal verdict is ACCEPT, REJECT or INCONCLUSIVE with a reason. Cancellation, budget halt, unavailable upstream tool and stale evidence all produce terminal records. Restart reconciles runtime instances before requeueing; uncertain prior execution never silently reruns a writing task.

## C8 — Autogenous bridge and sample resolver

Build a new small Rust CLI in LAB linked to the actual pinned Autogenous crates. JSONL input uses `schema: ak.lab-observer/v1`, `requestId`, `operation: observe|propose|evaluate`, and an operation-specific bounded body. Read one record at a time; maximum 64 KiB/record, 256 KiB buffered output, one request outstanding, 5-second processing deadline. Invalid input returns a closed error code; stdout never carries diagnostics or raw samples.

Use `StreamObserver::with_fingerprint_key`, `arm`, and `observe_chunk` for decoded fixture content. Decode Claude/Codex transcript fixture formats in a separate adapter; their JSONL is not provider SSE. The upstream SSE enum is `Google | OpenRouter | MetaLlm`, not `OpenAi`.

`resolveSample(incidentRef, grantRef): Promise<{sample: string; fixtureRef: string} | null>` reads only authorized training fixtures or separately approved sanitized samples, maximum 16 KiB. A fingerprint cannot reconstruct an attack. Absence yields `sample-unavailable`; it does not trigger raw transcript harvesting.

Pass the resolved sample to actual `autogenous_generator::propose` with a LAB experimental signing identity and fixed TTL (one hour initially). Evaluate generated detectors through upstream replay on independent labeled fixtures. Generator access excludes labels and acceptance shards. No service promotion endpoint, real traffic containment or real route change is wired in this plan.

## C10 — graduation bundle and mainline proposal

Task T18 follows [graduation-and-actions.md](graduation-and-actions.md). A laboratory champion becomes a draft proposal only through a sealed, single-use bundle; a GitHub merge remains outside LAB authority.

```ts
interface GraduationBundle {
  schema: 'ak.lab-graduation/v1';
  id: string; nonce: string; issuedAt: string; expiresAt: string;
  baselineSource: SourceBinding; candidateSource: SourceBinding;
  expectedMainSha: string; patchRef: string; patchDigest: string;
  acceptanceRef: string; anchorRef: string; cleanupRef: string;
  resourceRef: string; freshnessRef: string; receiptRef: string;
  rollback: { strategy: 'revert-pr'; parentRef: string };
  signer: { keyId: string; signature: string };
}
interface GraduationDecision {
  state: 'drafted' | 'denied' | 'stale' | 'expired';
  bundleRef: string; branch: string | null; pullRequest: number | null;
  reasonCodes: string[];
}
```

publishGraduation re-verifies signature, nonce, expiry, grant epoch, baseline SHA, patch and evidence references immediately before creating one draft PR. GitHub independently rebuilds and validates the PR commit. A local LAB verdict, artifact, signature or attestation cannot bypass repository review and branch rules.

`trainRouter(rows, prices, options)` requires options `{qualityBar:number, embeddingModelRef:string, k?:number}`. `publishDraft(artifactRef, grant:PublicationGrant, port)` checks local mode without remote calls, then verifies the referenced grant and artifact scope before any draft publication. A resolved object is not itself proof of signature validity.

Test helpers: `sourceBindingFixture()` in `tests/helpers.ts` returns all C4 fields using distinct synthetic SHA-256 references, a 40-character synthetic kit commit and a synthetic grant reference. `policyFixture()` uses those catalog references and every C2 initial limit. Helpers must be complete valid objects so a negative test fails on the field it intentionally changes.
