# Maintainer skills with an `ak-` prefix

## Status

**Active** (2026-10-03). The maintainer approved the design in chat on 2026-10-03 and this
file is waiting for their review. Nothing is implemented. Next step: the implementation plan,
`docs/plans/2026-10-03-ak-maintainer-skills.md`.

## Outcome

A maintainer types one word (`ship #438`, `release next`, `verify`, `resume`) and the agent
runs the repeatable runbook for it, with the safety rules the maintainer has had to repeat
by hand. The skills are for developing agentic-kit; they are not shipped to users.

Evidence behind the inventory: an audit of 111 session transcripts (726 maintainer prompts,
2026-09 to 2026-10). The merge-and-clean-up sequence was typed about 30 times, release about 21
times, "where are we" at least 4 times, and "post" 19 times. The word "verify" appeared in 26
prompts, and three incidents are on record of `pnpm test` changing real project or home state.

## Findings that shape the design

- `upstream-status` is the only authored skill. The other ~100 under `.claude/skills/`
  (`dual-mode` included) are generated by `aqe init` and claude-flow, are gitignored, and are
  rewritten on the next init.
- A skill is tracked through two narrow `.gitignore` exceptions (`.claude/skills/<name>/` and
  `.agents/skills/<name>/`) plus two `.gitattributes` lines, and
  `tests/kit/upstream-watch-skill.test.mjs` pins all of it. Each new skill would repeat that
  plumbing.
- The Claude and Codex copies of `upstream-status` are byte-identical.

## Decisions

1. **The prefix is the ownership marker.** `ak-<name>` means authored by this repository and
   tracked. Anything else under a skills folder is generated and ignored. Generated skills are
   not renamed or wrapped.
2. **Convention replaces per-skill exceptions.** `.gitignore` and `.gitattributes` use an
   `ak-*` glob for both hosts, so adding a skill touches neither file.
3. **Skills are prose runbooks that call existing scripts.** They restate no logic. A script is
   added only when a step is deterministic and unsafe to leave to prose (see
   [Mirror script](#mirror-script)).
4. **One text, two hosts.** `.agents/skills/ak-*` is a verbatim copy of `.claude/skills/ak-*`,
   produced and checked by a script.
5. **Authority gates are part of the skill text and are tested.** A skill never merges,
   publishes, posts, pushes or deletes without the maintainer's explicit yes on that specific
   action. This follows the repository rule that a coordination record never replaces
   authority.

## Authoring template

Every skill has the same parts, in this order, in a single `SKILL.md` under 500 lines:

1. Frontmatter: `name` (equal to the folder), `description` (what it does and the phrases that
   trigger it).
2. When to use it, and when not to.
3. Preflight: what to read or check before acting.
4. Steps, each naming the script or command it runs.
5. Gates: the actions that need an explicit yes.
6. Done: the evidence that closes the task.

## Mirror script

`scripts/skills-mirror.mjs` copies `.claude/skills/ak-*/` to `.agents/skills/ak-*/` verbatim
with LF endings. `--check` exits non-zero when the copies differ or a skill exists on one side
only. The test suite runs `--check`. This is the only new script; the skills themselves add none.

## Tests

`tests/kit/ak-skills.test.mjs` replaces `tests/kit/upstream-watch-skill.test.mjs`, keeping that
file's upstream-status assertions. It checks:

- the folder name equals `name:`, carries the `ak-` prefix, and exists for both hosts;
- the description holds at least one trigger phrase, and the file is under 500 lines;
- the two host copies are identical (through `skills-mirror.mjs --check`);
- every `scripts/*.mjs` file and `pnpm run` script a skill cites exists, and a cited
  `docs/` path exists;
- each skill contains its required gate phrases (the Gates column above);
- `git check-ignore` agrees that `ak-*` is trackable on both hosts and that generated skills,
  look-alikes (`ak-x` outside the skills folder, `upstream-status`) and nested copies stay
  ignored;
- `.gitattributes` pins every `ak-*` `SKILL.md` to LF.

Skill text is not executed by the tests. A runbook is exercised by using it: each skill gets
one dry run against this repository before the branch is finished, and the result is recorded
in the pull request.

## Docs

- `docs/maintainer.md` gains a "Maintainer skills" section: the convention, the table of
  skills and triggers, and how to add one.
- `AGENTS.md` gets a pointer to that section. `CLAUDE.md` imports it already.
- Living references to `upstream-status` (`docs/upstream-watch.md`, `docs/maintainer.md`,
  tests) become `ak-upstream-status`. Archived ADRs and plans keep the old name.

## Delivery

One branch, `feat/ak-maintainer-skills`, with unit commits:

1. Foundation: the glob rules, the rename, `skills-mirror.mjs`, the test file.
2. The eight new skills, written in parallel by writers that each own one folder.
3. Docs and the integration check.

Only the integration owner edits `.gitignore`, `.gitattributes`, `docs/maintainer.md`,
`AGENTS.md` and the test file. Writers get disjoint skill folders and run no shared-state
commands. Commits are local; the maintainer is asked before the first push.

## Open checks (done during implementation, before the docs claim them)

- `aqe init` and `ak sync` leave `ak-*` folders alone. Verify in a disposable `HOME` with
  `XDG_*` unset.
- The npm tarball excludes `.claude/` and `.agents/`. Verify with `npm pack --dry-run`.
- `pnpm test` does not touch `.claude/skills/` (the tripwire fingerprints `.claude`).

## Out of scope

- Renaming or wrapping generated skills.
- A user-facing skill catalogue; these skills are for maintainers.
- An ADR. The convention is small and lives in `docs/maintainer.md`. Say so if you want one.
