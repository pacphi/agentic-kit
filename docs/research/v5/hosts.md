# agentic-kit v5: six-host interoperability research

Research accessed **2026-09-25**. Local source baseline: `847486c61689f8499ada08f5b5684ecf26b22db8`. This memo used the repository before browsing current primary vendor documentation. Upstream capabilities below are documented capabilities, **not locally executed conformance results**. No hosts were installed, updated, authenticated, or invoked for paid inference. No credentials were read.

## Main conclusion

All six requested products now have documented automation surfaces, including an official **Grok Build CLI**. The v5 promise can be equal management quality across six hosts, with a capability-specific support contract. Identical native settings, hook behavior, billing visibility, and sandbox controls cannot honestly be promised. A host is the executable; provider and model are separate facts. In particular, Grok Build is a host, Grok models are also available through other hosts, and Grok Build itself documents custom model endpoints. [Grok Build](https://docs.x.ai/build/overview), [Grok in OpenCode](https://x.ai/news/grok-opencode).

## Existing implementation and ADR standing

The current built-in registry contains Claude, Codex, and OpenCode. Claude and Codex are primary eligible; OpenCode can route activities but is not primary eligible. Hermes, Gemini CLI, and Grok Build are not built-in host entries. This does not rule out a user-installed experimental adapter. The execution registry likewise includes three built-ins and an admitted external-adapter lookup. Sources: [host registry](https://github.com/pacphi/agentic-kit/blob/847486c61689f8499ada08f5b5684ecf26b22db8/src/lib/adapters/registries.mjs#L194), [execution registry](https://github.com/pacphi/agentic-kit/blob/847486c61689f8499ada08f5b5684ecf26b22db8/src/lib/execution/adapters.mjs#L9).

The right starting point is already present: four adapter axes (host, provider, projection, observability), provider bindings, detect/plan/apply/verify/undo lifecycle, and explicit conformance tiers. Avoid introducing a second independent host table into the dashboard. The current projection format enum has JSON, TOML, env, CLI, internal; Hermes needs a deliberate YAML/native-command strategy. [Registry validation](https://github.com/pacphi/agentic-kit/blob/847486c61689f8499ada08f5b5684ecf26b22db8/src/lib/adapters/registries.mjs#L68), [conformance harness](https://github.com/pacphi/agentic-kit/blob/847486c61689f8499ada08f5b5684ecf26b22db8/src/lib/adapters/conformance.mjs#L1).

Proposal: every cost figure should carry `observed_cost`, `provider_billed_cost`, or `api_equivalent_estimate`, currency, price-table date, source, coverage and aggregation grain. Do not add these categories together. Claude's own monitoring documentation says its cost metric is approximate; the provider's billing system is authoritative. A host label is insufficient to identify who served or billed an inference request. [Claude cost monitoring](https://code.claude.com/docs/en/monitoring-usage#cost-monitoring).

## What equal support should mean: testable v5 parity contract

This section is an engineering proposal derived from the sources above and the existing ak contracts, not a claim of delivered functionality.

1. **Discover:** identify executable, exact version, installation owner, user/profile/project context and supported capability range without starting inference. Multiple binaries on PATH are an explicit conflict state.
2. **Explain effective configuration:** for each field show desired value, observed effective value, originating file/scope, default/inherited/overridden/locked state, version applicability, restart requirement and writeability. A host-neutral label maps to explicit native semantics; native extensions remain available.
3. **Apply identically through UI and CLI:** both submit the same typed operation/plan with target scope and expected revision; validation and preview precede a content-preserving write. Compare-and-swap prevents overwriting edits made in another terminal. Verify the native effective result; keep an undo receipt only for the values ak changed.
4. **Execute safely:** begin, stream progress, report exactly one terminal result, distinguish authentication/permission/quota/tool failures, enforce absolute timeout, cancel descendants, clean up owned resources. Structured output is negotiated by installed version. Do not invent missing native controls.
5. **Observe honestly:** normalize IDs, parent/child relationships, timestamps, source/provider/model evidence, usage fields and missingness. Native events remain inspectable. A missing token field stays unknown; it does not become zero.
6. **Maintain:** check/plan/download/apply/verify independently, with pin/channel semantics and component ownership. An application being installed, the binary on disk being updated and a running session using the new build are three distinct states.
7. **Conform:** run common behavioral fixtures for all six hosts and OS/channel combinations in scope. Bind results to host version, adapter version and platform. Award separately discover/configure/run/observe/update capabilities; use the existing graduation machinery, extended where needed.

Useful common tests: setting inherited vs locked, malformed native config, user edits during preview, stale scope revision, expired auth, blocked permission, truncated/malformed JSONL, child failure, quota depletion, cancellation while tools run, interrupted update, package-manager mismatch, restart required, user-edited projection preserved, duplicate event replay, and absent usage. These are acceptance scenarios for later AQE implementation, not tests executed by this research worker.

## Host-specific work that v5 needs to respect

- **Claude:** preserve native/OS-package update ownership and channel semantics; map hooks and trust explicitly. Current ak print adapter already supplies stream JSON and schema output. [Local adapter](https://github.com/pacphi/agentic-kit/blob/847486c61689f8499ada08f5b5684ecf26b22db8/src/lib/execution/claude.mjs#L27).
- **Codex:** probe the installed configuration schema and profile representation. Current upstream documents separate profile files, so a UI hard-coded only to historic inline profile tables would be brittle. Current ak exec adapter preserves configured sandbox policy and uses runner timeout where no turn cap is forwarded. [Config](https://learn.chatgpt.com/docs/config-file/config-basic), [Local adapter](https://github.com/pacphi/agentic-kit/blob/847486c61689f8499ada08f5b5684ecf26b22db8/src/lib/execution/codex.mjs#L16).
- **Hermes:** model installation, profile, gateway and session separately. Two agent processes must not share one Hermes home. Code updates can affect all profiles even when settings target only one. Do not present a per-profile update button as an isolated binary update. [Profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles).
- **OpenCode:** keep authenticated loopback API supervision and explicit permission responses; server lifetime, session lifetime, and provider auth differ. Existing adapter is substantial and should be extended rather than replaced by a less capable terminal scraper. [Local adapter](https://github.com/pacphi/agentic-kit/blob/847486c61689f8499ada08f5b5684ecf26b22db8/src/lib/execution/opencode.mjs#L1), [Server](https://opencode.ai/docs/server).
- **Gemini:** OTel is opt-in but its telemetry documentation lists prompt logging as enabled within telemetry unless configured otherwise. The proposed shared observation preset should explicitly disable content logging while retaining operational metrics. Native hooks and MCP trust are distinct surfaces. [Telemetry](https://geminicli.com/docs/cli/telemetry/), [MCP](https://geminicli.com/docs/tools/mcp-server/).
- **Grok Build:** its hook discovery includes existing Claude and Cursor files. An ak-generated second copy can fire the same logical hook twice; native discovery inspection must drive deduplication. Project config cannot hold every user setting. Native statusline cost starts from the current process/resume and is not automatically lifetime session spend. [Hooks](https://docs.x.ai/build/features/hooks), [Settings](https://docs.x.ai/build/settings), [Statusline](https://docs.x.ai/build/features/status-line).

## Coarse and fine-grained updating: implications from real products

Proposal: a common update plan chooses **targets × components × channel/version × time × rollout policy**, then expands that selection into owned native actions. Offer all managed components, one host, one machine cohort, one plugin, one MCP package or an explicit dependency closure. Display shared-install effects before applying. Recheck drift and active sessions at run time; apply through the same operation service as UI and CLI.

Hermes provides a useful upstream precedent: machine-readable update receipts include a fleet plan, step results, skips and running version matrix. Its Docker path refuses the source updater and points to image replacement. An update launched inside its own gateway can defer restart because restarting that gateway can terminate the updater itself. These are concrete reasons for a supervisor independent of the workload it updates. [Hermes update design](https://hermes-agent.nousresearch.com/docs/getting-started/updating).

Proposal: schedule modes should include check-only, stage-only, apply-when-idle, and a maintenance window with optional canary cohort. Resolve timezone/DST, missed windows, jitter, offline catch-up, overlap locks, maximum duration, cancellation and retry limits explicitly. A scheduled write is governed by a durable policy covering component, version range, target cohort and allowed side effects, with its result receipt available in both UI and CLI. A cron string alone is not this product contract.

For immutable environments, the operation may produce an upgrade recommendation or desired image version for an existing deployment system. ak should not silently switch an install from an OS/package/image manager to its own installer. For changes requiring elevation or renewed auth, surface an actionable paused operation; do not claim scheduled success.

## UI implications

Proposal: a host card should show “Manage,” “Run,” “Observe,” and “Update” capability badges, each backed by versioned evidence, rather than a single ambiguous green compatibility check. A detailed drawer should show the effective configuration tree with “applies to: this project / this profile / this machine / managed organization,” immediate validation, a change preview, and a copyable equivalent CLI command. Native-only sections are first-class extensions with short explanations.

Proposal: keep “Grok Build” in Hosts and “xAI / Grok” in Providers; keep “Gemini CLI” distinct from the Gemini provider. A user may run a Grok model in OpenCode and still see the correct host, provider and payer. Teams need machine, person, host instance, profile, project and session as distinct identities, then labels as many-to-many metadata across projects/sessions. A profile is not a person; a running process is not the installation; the visual model should teach this through clear grouping.

## Uncertainty and release gates

This memo verifies published documentation, not on-machine runtime health. APIs, documentation and native scope handling are moving quickly. Certification must record the actual binary version and test fixture result, especially new Hermes/Gemini/Grok adapters, Codex profile compatibility, native update ownership and meaningful post-update runtime checks. No source here establishes universal OTel or exact provider billing for all six hosts. Treat these as separate certified extensions.
