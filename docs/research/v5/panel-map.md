# Existing dashboard → shared v5 panel map

Baseline: `847486c61689f8499ada08f5b5684ecf26b22db8`. Read-only static inventory, 2026-09-25. No runtime scan, installed-state read or repository mutation. This is an implementation inventory, not a claim that every panel currently has populated data.

## Grain and boundary

**101 functional panels/capability groups**, with one entry per meaningful chart, card group, inspector or action workspace. Individual KPI tiles, ordinary controls, table columns, legends, empty/loading states and repeated subsystem cards are recorded as capabilities of their parent. Conditional render-inserted scorecard panels are included. A shared Live/History renderer is counted once with both scopes; duplicating it would inflate the count. Dynamic component-directory cards are grouped under their existing section; all current card names are retained. Maintenance is decomposed into inventory, inspector, guidance, procedure, discovery, coverage, activity, history, receipt, recovery and apply rather than counted as one top-level tab.

Every entry has one canonical proposed home. **Every panel is shared across all six roles**; role focus changes attention/relevance while navigation and panel definitions remain stable. Saved compositions may reuse panels without creating alternate metrics or erasing access. Permission checks remain independent. Other homes may link/embed the same panel identity. Existing readonly panes stay readonly until an independently specified v5 write capability is implemented. All rows carry `status: existing`; only `proposedHome` and role composition are design choices.

Source anchors prefer actual DOM IDs. `groupCard-context` and `mnt-measurement-toolbar` are stable renderer/group names where no single parent DOM ID exists. The former is distinct from runtime pressure; the latter consolidates the existing shared measurement controls.
